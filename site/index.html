jkOS

jkOS is a self-hosted suite of web apps on TrueNAS SCALE: a portal, single sign-on, tasks and calendar, music and audiobooks, and a deploy console. It runs in Docker behind nginx with TLS, with separate staging and production.

Each security control is enforced in code and covered by a test. The three sections below show how sign-in, the audit log and deployments work.

Single sign-on and sessions

Sign-in and sessions
How it works · step throughRS256 · audience · 15 min · rotation
  1. You to jkAuth: sign inYou sign in once, at jkAuth.
  2. jkAuth to you: access token and refresh tokenjkAuth signs the access token with RS256. The private key never leaves jkAuth.
  3. You to the app: request with the access tokenThe browser sends the access token to an app.
  4. The app checks the tokenThe app verifies the signature with jkAuth's public key, then checks the issuer, the expiry and that the token names this app.
  5. The access token expiresThe access token is valid for 15 minutes.
  6. You to jkAuth: refreshRefreshing returns new tokens. The old refresh token is retired and can't be used again.
  7. Attacker to jkAuth: replay the old refresh tokenSomeone presents a refresh token that was already used.
  8. jkAuth revokes the sessionjkAuth revokes every token from that sign-in and logs a refresh_reuse event. The session rows stay, marked reuse.
  9. jkAuth to attacker: rejectedThe attacker is rejected. You sign in again.
  1. jkAuth signs tokens with RS256. The private key stays in jkAuth, and other apps verify with the public key. tokens.js
  2. Each token lists the apps it is valid for, and an app rejects a token meant for another app. Node backends refuse to start in production without this check. auth.js
  3. Access tokens expire after 15 minutes. Refresh tokens rotate on every use, and reusing an old one revokes the whole session. Sessions also have a maximum lifetime. tokens.js
  4. Revoked sessions are kept with a reason (logout, reuse or absolute_timeout), not deleted. Database triggers block reuse of a sign-in code and stop a session moving to another client. db.js
  5. security.mjs starts the real server and tries token replay, expired sessions and a token issued for the wrong app. security.mjs

How it works · select a stepone trusted proxy

What each step records:

  1. RequestNothing yet. An IP address the client claims for itself is ignored.
  2. nginxThe client's real IP. jkAuth trusts exactly one proxy hop, and won't start if that setting changes.

jkOS · KourOS

Vibe map: embeddings and linear algebra

  1. Audio to mel spectrogramEach track's audio becomes a mel spectrogram: how much energy sits in each frequency band over time.
  2. 512 numbers per trackA pretrained audio model (CLAP) turns the spectrogram into a 512-dimensional vector. 47,691 tracks are measured.
  3. Cosine similarityTracks that sound alike point the same way. A raw comparison first made the hand-built baseline look better. That was an artifact of the model's narrow, cone-shaped space, and standardizing the gap fixed it.
  4. Four axesThe map reduces 512 dimensions to four. Energy comes from a ridge regression probe and is removed first, so PCA's three spatial axes show everything except energy. UMAP and t-SNE were rejected because they give no stable coordinates.

The model is pretrained. At this library size, training one wasn't the right call. The work is the pipeline, the math and these checks:

  • Pass and fail thresholds were fixed before the first real fit.
  • A fit that fails is refused. The map is marked "held" instead of shipped.
  • If the analysis config changes, the index refuses writes (ConfigDriftError).
  • The app checks five reference tracks against their stored coordinates before it trusts the map.

jkOS · CONTROLS.md

Controls matrix

22 controls. Each lists the risk, the code that enforces it, the test that proves it and the audit event it records.

  1. AC-1 Passwords are hashed with bcrypt over a SHA-256 pre-hash, so input of any length is fully hashed.

    Risk
    Bcrypt silently truncates at 72 bytes, so two long passwords sharing a prefix would verify as one.
    Enforced in
    apps/jkauth/src/password.js
    Proved by
    apps/jkauth/test/smoke.mjs
    Evidence
    password_change password_reset

  2. AC-2 Repeated failed sign-ins lock the account for a window. This includes the shared guest account.

    Risk
    Online password guessing.
    Enforced in
    apps/jkauth/src/routes/auth.js
    Proved by
    apps/jkauth/test/smoke.mjs apps/jkauth/test/security.mjs
    Evidence
    login_fail login_locked guest_login_fail

  3. AC-3 A second factor (TOTP or emailed code) is available per user. The TOTP secret is sealed with AES-256-GCM, and enrolment is refused when no sealing key is configured. Recovery codes carry 80 bits.

    Risk
    A stolen password alone signs in. A database copy leaks every TOTP seed. Short recovery codes are cracked offline.
    Enforced in
    apps/jkauth/src/twofactor.js apps/jkauth/src/secretbox.js
    Proved by
    apps/jkauth/test/security.mjs
    Evidence
    login_2fa_fail

  4. AC-4 Tokens are RS256-signed by jkAuth alone. Every other service verifies them against the published public key, in Node and in Python.

    Risk
    A forged or tampered token, or a second signer drifting from the first.
    Enforced in
    apps/jkauth/src/tokens.js packages/auth-middleware/index.js jkos-deploy/jkos_auth.py
    Proved by
    apps/jkauth/test/contracts.mjs packages/auth-middleware/test/jwks.mjs
    Evidence
    none

  5. AC-5 A token is accepted only by the apps its audience names. Every Node backend refuses to start in production without an audience to check.

    Risk
    One cookie reaches every *.jkos.net host, so without this a token minted for one app is spendable at all of them.
    Enforced in
    packages/weave/src/server/auth.js apps/jkauth/src/tokens.js
    Proved by
    apps/jkauth/test/security.mjs packages/weave/test/weave.mjs
    Evidence
    none

  6. AC-6 Production and staging use different token issuers and cookie names, so a session in one grants nothing in the other.

    Risk
    A staging credential, which is easier to obtain, opens production.
    Enforced in
    packages/auth-middleware/index.js apps/jkauth/docker-compose.staging.yml
    Proved by
    apps/jkauth/test/contracts.mjs
    Evidence
    none

  7. AC-7 Least privilege comes from one table: a route names an action and the policy module decides. No route compares roles itself.

    Risk
